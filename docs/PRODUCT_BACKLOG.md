# 🎯 Product Backlog: R-NET (Sistem Pendaftaran Internet Provider)

Dokumen ini berisi Product Backlog terstruktur untuk pengembangan **R-NET (Sistem Pendaftaran Internet Provider)** yang telah diselaraskan sepenuhnya dengan model XMI Use Case pada [UseCase_RNET.xml](file:///e:/SEMESTER4/PBL/Indeks/UseCase_RNET.xml) dan skema database riil.

---

## 👥 Aktor & Peran Sistem (Berdasarkan UseCase_RNET.xml)
1. **Calon Pelanggan**: Mengakses portal publik untuk melihat informasi paket, promosi, pengumuman, melakukan pendaftaran, mengunggah foto depan rumah, dan memantau status pendaftaran.
2. **Admin (Administrator)**: Mengakses admin panel untuk login/logout, melihat dashboard, mengelola data pendaftaran (view, status, hapus), melakukan CRUD paket internet, CRUD promosi, CRUD pengumuman, CRUD area layanan, membarui profil admin, dan memperbarui informasi profil perusahaan.
3. **Developer**: Mengakses admin panel khusus untuk login/logout, melihat dashboard, memantau grafik tren, melakukan monitoring server (RAM, OS, PHP, Laravel load time), monitoring database & storage (PostgreSQL, Supabase S3), serta memperbarui profil developer.

## 💡 Catatan Tambahan bagi Tim Developer R-NET
1. **Penerapan Arsitektur SPA**: Seluruh fitur manajemen admin (US20002 s/d US20010) dan developer (US30002 s/d US30004) dikembangkan dalam format Single Page Application (SPA) berbasis Vanilla JS yang ada di dalam `resources/views/admin/index.blade.php`. Pastikan modifikasi UI menggunakan DOM manipulation asinkron via `fetch` API tanpa melakukan reload halaman penuh.
2. **Koneksi Supabase S3**: Perhatikan setup kredensial bucket di file `.env`. Untuk US10003 dan US20005, kegagalan koneksi dengan S3 harus ditangani secara asinkron agar tidak memicu error *Fatal Crash* (500) pada server utama.
